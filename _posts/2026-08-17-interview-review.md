> 이직을 준비하면서 받았던 면접 질문들을 그때그때 메모해뒀었다. 시간이 좀 지난 지금, 그 메모들을 다시 꺼내서 어떻게 답했는지, 지금 다시 받는다면 어떻게 답하고 싶은지 복기해본다.

![예상 못한 질문에 당황](thumbnail.png){: width="580" height="328" }
_면접장에서 실제로 이랬음,,_

M사(MSP 업체), H사 계열 광고대행사 두 곳의 면접 메모를 정리했다. 실제 질문과 답변은 최대한 솔직하게(부끄럽지만) 복기해본다.

#### <i class="fas fa-building fa-fw"></i> **M사(MSP 업체) — 1차 면접**

**기술 질문**은 대부분 이력서/포트폴리오에 적어둔 프로젝트를 근거로 파고드는 식이었다.

- BigQuery 파티셔닝과 클러스터링의 차이
- Airflow에서 Sensor의 역할
- 메달리온 아키텍처와 스타 스키마
- GCS에 왜 Parquet으로 적재했는지
- Flex API에서 왜 Cloud Function과 API Gateway를 선택했는지
- Text2SQL도 이력서에 적어놨는데, 딥하게 구현해본 게 맞는지
- Airflow의 의존성 관리, task 정의 방식
- API 키를 key/salt 구조로 만든 이유

이 중 Text2SQL 질문은 "그렇게 딥하게 구현한 건 아니다"라고 정직하게 답했었는데, 지금 돌이켜봐도 이건 잘한 답변이라고 생각한다. 이력서에 적은 키워드를 면접관이 그대로 파고드는 건 당연한 일이라, 어설프게 아는 척하는 것보다 "여기까지는 해봤고, 여기서부터는 못 해봤다"를 명확히 긋는 게 오히려 신뢰를 준다.

반면 Airflow 의존성 관리 질문은 조금 얼버무렸던 기억이 있다. `>>` 연산자로 task 순서를 정의하는 수준이 아니라, `trigger_rule`이나 `TaskGroup` 같은 걸 예시로 들면서 "단순 순서가 아니라 실패 전파 방식까지 설계했다"는 식으로 좀 더 구체적으로 답했으면 훨씬 나았을 것 같다.

> 아는 건 아는 대로, 모르는 건 모르는 대로 정직하게 답하되 - 아는 부분은 최대한 **구체적인 코드 레벨**까지 내려가서 답하자.
{: .prompt-tip }

**조직/협업 관련 질문**에서는 꽤 날카로운 질문이 하나 있었다. 데이터플랫폼 파트 인원이 3명이라고 답하니 "그럼 사수가 시키는 일만 했겠네요?"라고 되물으신 것. 당시엔 "파트장님과 나이 차이도 크지 않고 수평적인 조직이라 하고 싶은 일을 주도적으로 할 수 있는 환경이었다"고 답했는데, 지금 보면 방향은 맞았지만 근거가 좀 추상적이었다. "그래서 실제로 내가 제안해서 시작한 프로젝트가 이거였다"는 구체적인 사례 하나를 붙였으면 훨씬 설득력이 있었을 것 같다.

저연차 3명이서 일하면서 확신 없이 방황했을 때 어떻게 했냐는 질문에는 "그래서 이직을 결심했다", "컨퍼런스나 설명회에 가서 명함 교환하고 커피챗을 하다가 이직으로 이어졌다"고 답했다. 사실 그대로이긴 한데, 지금 다시 생각해보면 이 답은 "힘들어서 도망쳤다"로 들릴 위험이 있다. 방황하던 시기에 스스로 뭘 시도해봤는지(사내에서 리뷰 문화를 만들려고 했다든지) 먼저 얘기하고, 그럼에도 한계가 있어서 더 큰 조직/더 시니어한 동료들과 일하고 싶어졌다는 흐름으로 답했으면 훨씬 능동적으로 들렸을 것 같다.

**회사 핏 관련 질문**들, 예를 들어 "우리가 뭐 하는 회사인지 아냐", "같은 그룹 내 다른 계열사와 우리 회사의 차이를 아냐" 같은 질문에는 솔직히 준비가 부족했다. k8s 경험을 묻는 질문에도 "안 해봤다"고만 답하고 넘어갔는데, "안 해봤지만 이런 식으로 학습할 계획이다"까지 덧붙이는 습관을 들여야겠다.

#### <i class="fas fa-building fa-fw"></i> **H사 계열 광고대행사 — 1차 면접**

H사 계열 광고대행사 1차는 실제 프로젝트 아키텍처를 상당히 깊게 파고드는 면접이었다.

- Bronze → Silver → Gold로 넘어가는 레이어마다 품질 검증을 어떻게 했는지
- Gold까지 온 데이터에 오류가 발견되면 어떻게 거꾸로 되돌릴 것인지
- 타이트한 클라이언트 데드라인에는 어떻게 대응할 것인지
- 권한 관리는 어떻게 했는지
- 4시간마다 도는 배치인데, 왜 Serverless가 아니라 VM을 썼는지
- Gold 레이어(마트)는 어떻게 구성했는지
- 본인의 장점(끈기/꼼꼼함/책임감)을 증명한 사례가 있는지
- "정말 하고 싶은 게 뭐냐, 스타트업에서 이것저것 다 해보고 싶은 것인지"

이 중 가장 아쉬웠던 건 Serverless 대신 VM을 쓴 이유를 묻는 질문이었다. 당시엔 명확한 트레이드오프 근거 없이 답했던 것 같은데, 지금 생각해보면 "콜드 스타트로 인한 배치 지연", "Airflow 워커와 같은 네트워크 안에서 상태를 공유해야 했던 점", "장시간 실행되는 태스크가 섞여 있어 실행 시간 제한이 있는 Serverless보다 VM이 더 안전했다" 같은 근거를 미리 정리해뒀어야 했다.

"정말 하고 싶은 게 뭐냐"는 질문도 그 자리에서 즉흥적으로 답하기엔 무거운 질문이었다. 커리어 방향성을 한두 문장으로 정리해둔 게 없어서 다소 두루뭉술하게 답했던 기억이 있다. 이런 질문은 미리 준비해두지 않으면 꼭 이렇게 허를 찔린다.

장점을 증명하는 사례를 묻는 질문 역시 마찬가지다. STAR(상황-과제-행동-결과) 형식으로 미리 정리해둔 사례가 없어서 즉흥적으로 답했는데, 면접 때마다 반복적으로 나오는 유형의 질문인 만큼 사례 3~4개는 미리 문장으로 정리해뒀어야 했다고 생각한다.

#### <i class="fas fa-building fa-fw"></i> **H사 계열 광고대행사 — 2차 면접**

2차는 조직 문화와 커리어에 대한 이야기가 중심이었다.

- 1차 면접에서 받았던 질문 중 가장 인상 깊었던 게 뭔지
- 지금 팀장님의 성향과, 그런 분과는 어떻게 일하면 좋을지에 대한 조언
- "너무 일만 하지 말고 세상을 좀 봐라"는 이야기
- 자동차 데이터라고 너무 대단한 걸 기대하지 말라는 조언 (차량 재구매 리드타임이 길어서, 데이터로 전환율을 극적으로 높이기 어려운 도메인이라는 설명)
- 출신 학교, 데이터 사이언스 전공 커리큘럼에 대한 질문

2차는 기술 질문보다 "이 사람과 같이 일하고 싶은가"를 보는 자리에 가까웠다. "1차에서 가장 인상 깊었던 질문"처럼 메타인지를 요구하는 질문에는 그 자리에서 순발력 있게 답하기가 유독 어려웠는데, 면접이 끝나고 나서도 계속 곱씹게 되는 걸 보면 이런 유형의 질문이 오히려 지원자의 진짜 관심사를 잘 드러내는 것 같다.

데이터 관련 조언은 인상 깊었다. 기술이나 조직 얘기가 아니라 도메인 자체의 한계를 미리 알려주는 피드백이었는데, 이런 얘기를 들으면 "이 회사가 지원자에게 헛된 기대를 심어주지 않으려 한다"는 신뢰가 생긴다.

#### <i class="fas fa-list-check fa-fw"></i> **다음 면접을 위한 체크리스트**

두 회사의 메모를 다시 훑어보니, 아쉬웠던 지점들이 몇 가지 패턴으로 반복된다는 걸 알게 됐다. 다음 면접 전에는 최소한 아래 항목들을 미리 정리해두려고 한다.

- **아키텍처 의사결정 근거** : "왜 이 기술을 썼는지"류의 질문(서버리스 vs VM, Cloud Function vs API Gateway 등)에 대한 트레이드오프 근거를 프로젝트별로 미리 문장으로 정리해두기
- **STAR 사례 3~4개** : 장점/책임감/문제해결 경험을 묻는 질문에 바로 꺼낼 수 있도록 상황-과제-행동-결과 형식으로 미리 정리
- **커리어 방향성 한 줄 요약** : "정말 하고 싶은 게 뭐냐" 류의 질문에 즉흥적으로 답하지 않도록 미리 문장으로 정리
- **모르는 건 정직하게, 대신 학습 계획까지** : "안 해봤다"로 끝내지 않고 "그래서 이렇게 채워나갈 계획이다"까지 붙이기

#### <i class="fas fa-flag-checkered fa-fw"></i> **마무리**

메모만 보면 좀 당황스러웠던 순간들도 많았는데, 이렇게 다시 정리해보니 그 안에서도 잘 답했던 부분과 아쉬웠던 부분이 꽤 선명하게 갈린다. 특히 기술적인 트레이드오프 질문들은 준비 없이 즉흥으로 답하기엔 항상 아쉬움이 남는다는 걸 다시 느꼈다.

다행히 두 곳 모두 합격 소식을 받았다. 돌이켜보면 완벽한 답변만 늘어놨던 건 절대 아니고, 오히려 얼버무리거나 준비가 부족했던 순간이 더 많았던 것 같은데도 좋은 결과로 이어진 걸 보면, 면접이란 게 매 순간 완벽한 정답을 말해야만 통과하는 자리는 아닌 것 같다. 다만 그렇다고 이 아쉬움들을 그냥 넘기고 싶지는 않다. 다음 면접부터는 위 체크리스트를 미리 정리해두고, 이번보다 조금 더 여유 있게 답하고 싶다.
